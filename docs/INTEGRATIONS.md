# One laboratory, four research lenses

Existing ecosystem conventions were inspected in the local HNS, CTX, SEC, EVL and root repositories. Their public homepages returned HTTP 200 during implementation. ARL provides reciprocal outbound theory links; it does not modify those separate repositories or the root canonical registry.

| Research system                   | ARL execution view                                                    |
| --------------------------------- | --------------------------------------------------------------------- |
| [HNS](https://hns.aserdargun.com) | Orchestration, tools, transitions, retries, budgets and observability |
| [CTX](https://ctx.aserdargun.com) | Context assembly, retrieval, provenance, memory policy and state      |
| [SEC](https://sec.aserdargun.com) | Identity, delegated purpose, scope, expiry, boundaries and approval   |
| [EVL](https://evl.aserdargun.com) | Deterministic verification, evidence and outcome contracts            |

These remain research/concept systems. ARL is their shared execution laboratory, not four parallel simulations or a duplicate essay collection.

Deeper compute layers: ARL's model call → [TFL serving](https://tfl.aserdargun.com) → [GEX GPU execution](https://gex.aserdargun.com). ARL stops at the model-call abstraction and does not implement serving schedulers, KV caches, warps or physical hardware. Toward the world, ARL → authorized action → simulated report.

“Intent → agent → token → silicon → action” is a conceptual learning stack, not a claim that those components execute once in a literal linear order. Root-site integration, external trace import and production domain binding are separate release work.
